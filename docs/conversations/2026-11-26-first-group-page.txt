  Bombadil

  It drives a real Chrome with random clicks, typing, back, and reload, and
  checks properties written in TypeScript after every step. It is MIT-licensed,
  at version 0.8.0, and has broken compatibility between minor versions, so we
  would pin it.

  - Found a real fault in its first second. With the settings .env.example
    ships, the security policy blocks Datastar, so nothing interactive can run.
    The fault was already noted in an old diary entry, but no Go test catches
    it. I recorded it as a must-fix before the first interactive page.
  - Custom checks work. A small check of the agent's own covered 1,214 page
    states in a minute and found that the home page has an empty title.
    Replaying the saved run reproduced it.
  - Limits. It cannot read email, drive two people at once, or look at the
    database. The trial only had a placeholder page to explore, so how it
    behaves on a real timeline is unknown.

  Proposed plan

  Kind of test: Unit and integration, against real SQLite and the real router
  What it is for here: Every behaviour, and every verdict you give
  When it runs: Every pull request
  ────────────────────────────────────────
  Kind of test: Property-based with hegel, simple
  What it is for here: Grouping by day across time zones, escaping of post
    text, paging, sign-in tokens
  When it runs: Every pull request
  ────────────────────────────────────────
  Kind of test: Property-based with hegel, stateful
  What it is for here: Generated sequences of actions: people and roles,
    sign-in links working once and expiring, timeline order and the "new"
    marks
  When it runs: Every pull request, longer runs nightly
  ────────────────────────────────────────
  Kind of test: Go fuzzing
  What it is for here: Anything that parses what a person sends: form values,
    paging cursors, later Markdown and photo uploads
  When it runs: Short on every pull request, longer nightly
  ────────────────────────────────────────
  Kind of test: Bombadil
  What it is for here: Browser faults, plus product rules as checks per role,
    such as "a comment once shown never vanishes without a note"
  When it runs: A short run per piece of work, nightly on main, not a merge
    gate until it has run a while without false alarms
  ────────────────────────────────────────
  Kind of test: Screenshots and the preview
  What it is for here: Your look
  When it runs: Every piece of work

  The three-role permission table gets a plain table test; it is too small to
  need generated cases.

  Decided by me, for you to overrule:

  - Clock and randomness are injectable from the first build. Expiry tests and

  - One test-only sign-in, compiled out of production. Bombadil and your preview
